# 通用文档 RAG 首版需求规格

- 日期：2026-10-04
- 状态：用户已批准收缩范围；本文件替代此前完整产品规格；首期功能已实施，验证见 docs/verification/general-rag.md。
- 形态：本机单用户，Gradio 页面和 CLI，页面直接调用 Python 核心，无独立业务 API。

## 1. 目标与范围

复用现有 RAG 栈，支持任意文档知识库，完成：创建知识库 → 上传文件或添加目录 → 手动全量重建 → 带引用问答 → 删除知识库。

保留 Python 3.11+、Gradio、LlamaIndex、Qdrant、本地 Embedding 和 OpenAI-compatible LLM。包名 t_rag，不建设通用插件框架。

### 知识库

- 创建、列出、选择、删除知识库；稳定随机 ID，与显示名称分离。
- 问答必须指定一个知识库，首版不跨库查询。
- 删除前页面确认，仅清理该库集合和应用管理文件，不删除目录数据源原始文件。
- 同名知识库不允许重复创建；改名留到后续。

### 文档导入

- 支持上传文件和添加任意本地目录；目录排除规则由数据源配置，不包含固定金融项目路径或 bxf 排除。
- 上传复制到管理目录；同一上传来源的同名文件再次上传视为替换。同名文件在不同数据源中使用不同文档 ID。
- 目录文件只读，重建时扫描其当前内容；缺失文件不进入新索引。扫描不会删除源文件。
- 支持 UTF-8 Markdown/MDC/TXT、可提取文字的 PDF、CSV、XLSX。
- 处理 PDF 全部页、XLSX 全部非空行及 CSV 全部记录。不可静默截断；无法处理则明确报错。
- 保留 Markdown 章节、PDF 页码、表格工作表/行范围，便于定位引用。
- 可移除数据源或上传副本，随后必须手动重建；不提供独立逐文档增量更新/删除任务。

### 手动重建

- 每个知识库一个 Qdrant 集合及一份 DocStore，全量重建代替增量同步。
- 状态为未建索引、需要重建、重建中、可用、失败；进度由 Gradio 展示，不建立独立任务系统。
- 重建前先标记不可查询；重建期间该库暂停问答。失败不承诺保留旧版服务，状态保持失败，用户可重新重建。
- 只有向量和 DocStore 均成功完成并校验后才标记可用。重启后重建中状态视为失败，不自动恢复任务。
- 同一进程写操作串行；索引与查询协调，不能边覆盖集合边查询。首版不支持页面和 CLI 多进程同时写。
- 上传、来源变更后标记需要重建；查询前检查已索引文件哈希清单，目录内容变化时要求重建，避免无提示使用旧内容。
- 保存索引配置签名；Embedding 模型、地址、维度或切分配置改变后拒绝使用旧索引并提示重建。

### 检索问答

- CLI query 与 ask、页面问答共用检索入口，支持向量、BM25、融合，默认融合。
- 两路均限定所选知识库；BM25 使用同一知识库 DocStore 的叶节点。
- 移除固定业务域、金融术语改写、产品号和渠道提取及产品号回答校验。
- 向量门槛作用于原始相似度，BM25 保留词项命中的候选，融合分数只用于排序；不取消门槛兜底。
- 无来源时不调用 LLM，提示证据不足。空答案、无引用、越界引用均拒答。
- 页面展示回答、来源片段和位置；仅预览知识库登记的内容，不能通过任意路径读取文件。
- 引用有效不保证事实正确，评测记录证据一致性和拒答效果。

### 配置

- 模型、路径和切分参数通过 YAML 与 T_RAG_* 环境变量配置；首版不做页面设置编辑器或旧命名兼容层。
- 密钥仅通过环境变量或本地未入版本控制配置提供，不进入知识库清单、索引元数据或日志。
- 说明远程 LLM 会收到检索片段，本地 Embedding 服务和 Gradio 仍通过 HTTP 工作。

## 2. 页面

三个区域：知识库管理、文档与重建、问答。显示当前知识库及索引状态，提供来源列表、重建进度和失败原因；可展开检索片段辅助排查，不新增复杂调试面板。

## 3. 数据及目录

每个知识库在 data/t_rag/<ID>/ 保存 manifest.json、uploads/ 和 docstore/；Qdrant 集合为 t_rag_<ID>。

清单包含知识库名称/ID、数据源、索引状态/错误、文件哈希和索引配置签名。用原子文件替换保存 JSON，保存失败不能宣称成功。无需 SQLite、文档版本表或索引发布记录。

源码仍按 knowledge、ingestion、retrieval、qa、models、storage、web 组织；tests/unit 按模块组织，实际集成和浏览器用例放 tests/integration、tests/e2e。文档放 docs/spec、docs/plan、docs/verification。

## 4. 开发与验证

遵循 [开发规则](../rules/dev-rule.md)，沿用类型标注、snake_case 和 dataclass。例如服务入口：

```python
def retrieve(settings: Settings, knowledge_base_id: str, question: str):
    ...
```

基线命令：

```bash
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 .venv/bin/python -m pytest -q
scripts/start.sh web --host 127.0.0.1 --port 7860
scripts/start.sh embeddings
```

验收：

- [x] 创建两个知识库，同名来源和相同关键词在向量、BM25、融合中均不串库。
- [x] 任意目录/上传文件可导入，重复导入与重建无重复片段。
- [x] PDF 第11页、XLSX 第11行可检索且引用位置正确。
- [x] 来源移除或文件变化后提示重建；成功重建后旧片段消失。
- [x] 重建中、失败和重启中断不允许查询部分索引，重试可恢复。
- [x] Embedding/切分变化明确要求重建；无引用、越界引用、空库和无来源正确拒答。
- [x] 删除知识库后应用资源被清理，目录原始文件仍存在；清理失败可重试。
- [x] 完成真实本地 Qdrant/Embedding 集成与浏览器闭环，单独记录真实 LLM 是否验证。

## 5. 边界

始终检查知识库归属、保存失败状态和来源位置，运行相应测试；不提交密钥，不操作原文件，不新增独立业务 API。

不在首版：SQLite、索引版本切换/回收、独立后台任务与重启续跑、逐文档增量更新、目录差异确认工作流、页面模型设置、旧命名兼容、OCR、网页/数据库、权限、多轮历史、流式生成、缓存、父节点回灌、重排。

原 data/docstore 与 fin_rag_docs 不迁移或删除；新系统独立使用 data/t_rag 与 t_rag_ 集合前缀。范围变更、旧数据迁移或代码提交/推送需另行授权。
